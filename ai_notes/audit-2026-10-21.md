# asql code audit, 2026-10-21

Scope: everything after PRs #2–#4 (lossless Visual ASQL round trip, contributor
setup, docs-corpus fixes) on `main` at `64d64a0`. Three passes:

1. **Docs corpus**: all 217 ` ```asql-play ` blocks through parse, three
   dialects, and the visual round trip. Fixed in #4; the two leftovers are
   parser bugs below (P-A1). The corpus is now part of
   `tests/test_visual_roundtrip.py`.
2. **Parser** (`asql/dialect/parser.py`, `tokenizer.py`, `transforms/`): a
   read-only review agent probing documented syntax; every finding re-run by
   hand before listing.
3. **Compiler** (`asql/transpile.py`, `asql/compiler/*`): same method, with
   DuckDB execution proofs where a wrong result could be shown.

Severity: **Critical** = silently wrong results or dropped clauses on
documented syntax; **High** = invalid SQL or wrong results on a documented
form; **Medium** = wrong on less common input or dialect-dependent.
Reproductions use `asql.transpile(q, write=...)` unless noted.

## Parser

| # | Sev | Finding | Reproduction | Where / fix |
|---|---|---|---|---|
| P1 | Critical | Unparsed tokens are silently discarded at every transform boundary. Root cause of P2 and others. | `from t where x = 1 foo bar baz` → `SELECT * FROM t WHERE x = 1`; `from t select a, , b` → `SELECT a FROM t` | `_parse_asql_expression_until_transform_boundary` / `_parse_asql_select_expressions_until_transform_boundary` end with `_consume_tokens_until_index`. Raise "Unexpected token" when `_index < end_index` after the parse. |
| P2 | Critical | `when … then <binary expr>, otherwise …` drops the ELSE branch and the alias. | `from t select when status is "a" then y + 1, otherwise 0 as z` → `SELECT CASE WHEN status = 'a' THEN y END + 1 FROM t` | `_parse_when_result` uses `_parse_unary`; use `_parse_assignment`. |
| P3 | Critical | Underscore shorthand re-aggregates an alias produced by an earlier stage; breaks the spec's own §11.2 example. | spec §11.2 → `revenue AS (SELECT country, SUM(users) AS total_users FROM __tmp1)`; `from users select last_login, min_price` → `MIN(price) AS min_price` | `transforms/underscore_shorthands.py` expands any `prefix_rest` name without a schema. Never expand an output column of the source stage (`_pipe_cte_output_columns`); consider schema-less expansion opt-in. |
| P4 | High | Auto-aliasing injects `AS` inside function argument lists. | spec §4.10 `concat(upper(first), " ", last) as n` → `UPPER(first) AS upper_first \|\| ' ' \|\| last AS n` (DuckDB syntax error); `explode split(tags_csv, ',') as tag`; `where name contains lower(other)` | `transforms/auto_alias.py` aliases every `expressions` list. Alias only direct projections of `exp.Select`. |
| P5 | High | `first()/last()/arg_max()` inside an aggregate block emit window functions in a GROUP BY query. | spec §5.7 `group by customer_id ( first(order_id order by -order_date) as latest_order )` → `FIRST_VALUE(...) OVER (...) … GROUP BY customer_id` (binder error) | `_parse_first_ordered` etc. Build `exp.ArgMax/ArgMin` in aggregate context. |
| P6 | High | `except`/`rename` after a join silently lose their exclusions. | spec §13.1 `from users & orders on … except users.password_hash` → `SELECT users.*, orders.*` | Column ops drop the qualifier; `auto_qualify` replaces the `Star` and discards `except_`. Move the list onto the matching `table.*`. |
| P7 | High | Steps after `limit`/`offset` are hoisted above them. | `from orders limit 10 where x = 1` → `WHERE x = 1 LIMIT 10`; same for `group by`, joins, `per … first` | `_apply_pipeline_transform` only stages on `group`. Once `limit`/`offset`/`sample` is set, any following step must go through `_build_pipe_cte`. |
| P8 | High | A second `select`, an `extend`, or a `where` after an aliased `select` does not stage. | `from t select a + 1 as c select c, 2 as d` → `SELECT c, 2 AS d FROM t`; `select a, b extend a + b as c` loses `a, b` | Close the stage when `query.expressions != [Star]` before SELECT/EXTEND/WHERE/joins (the rule already used before GROUP BY). |
| P9 | High | `when … is null` compiles to `= NULL` (always false); non-identifier bases emit SQL `IS 'A'`. | `when status is null then 1, otherwise 0` → `CASE WHEN status = NULL …` | `_parse_when`: parse the base with `_parse_column`/`_parse_primary`; build `exp.Is` for NULL/booleans. |
| P10 | Medium | Chained joins fail when an `on` condition has anything but `col = col [and\|or …]`. | `from a & b on a.id = b.a_id and b.amount > 10 & c on c.id = b.c_id` → ParseError | `_parse_on_expr_with_join_stop` hand-rolled grammar; reuse the boundary-retype trick with `_parse_assignment`. |
| P11 | Medium | Spec'd `&` as AND inside `where` is parsed as bitwise AND. | spec §9.2 `where status = "open" & owner.is_active` → `status = 'open' & owner.is_active` | Treat a non-join `AMP` as `exp.And` in the where payload, or drop the form from the spec. |
| P12 | Medium | `select *, expr as new_col` excludes a column that does not exist and needs a schema on Postgres. | `from users select *, 1 as flag` → `* EXCLUDE (flag)` (DuckDB binder error); every `select *, … as x` fails on Postgres without a schema | `_apply_star_column_override` with unknown source columns. Record the intent in `meta`; apply the exclusion only when a schema proves the column exists. |
| P-A1 | High | `first(x order by y) over cohort` (named window) is not parsed: the rest of the projection is dropped and the window is aliased `over`. Two docs cohort examples (`docs/examples.md`) compile to this; both are `xfail` in the round-trip corpus. | `select *, first(customers order by period) over cohort as cohort_size, running_sum(revenue) over cohort / cohort_size as ltv` → `SELECT *, FIRST_VALUE(customers) OVER (ORDER BY period) AS over` | Same root cause as P1; also needs named-window support or a parse error. |

Lesser parser findings (all reproduced by the agent): `rename`/`replace` directly after a `select` list → ParseError (`_parse_alias` guard checks only `VAR`); bare `group by` then `order by`/`having` emits `SELECT * … GROUP BY` (invalid); SELECT-first statements with a trailing transform are re-parsed with a fresh dialect and lose `SET`/schema; `stash as x;` then `from x` as a new statement has no `WITH`; own-line comments before a transform keyword are dropped; `group by day of week sale_date (…)` and `group by date (…)` → ParseError; `@2024-01-15T10:30` silently becomes a DATE; `select # orders.id` → `COUNT(orders)`; multi-line arithmetic starting with `*` becomes a cross join; `matches` is REGEXP while the spec promises LIKE semantics; `::PST` / `::INTEGER?` documented but unimplemented; `per x first by -a, b` → ParseError; misleading "aggregate block after a SELECT query" error for `string_agg`/`median`/`first` in a block; `select a, b except b` still projects `b`; `SET bogus = 1` accepted silently; comment-only statements emitted after `SET passthrough_comments = false`; every ascending `order by` emits an explicit `NULLS FIRST` (opposite to DuckDB/Postgres/Snowflake defaults, undocumented); `in (from users … select id)` nested FROM-first → ParseError; `pivot`/`unpivot` on Postgres compile to `SELECT * FROM sales` (clause dropped with only a sqlglot warning).

## Compiler

| # | Sev | Finding | Reproduction (DuckDB execution unless noted) | Where / fix |
|---|---|---|---|---|
| C1 | Critical | `week()` spine with Sunday weeks returns NULL for every period. | `SET week_start = sunday; from orders where d >= @2024-01-01 and d < @2024-02-01 spine by week(d) (sum(amount) as rev)` → every `rev` is NULL (data has 3 weeks of sales) | `compiler/spine.py` `_apply_spine_transform` builds the join key as Monday `DATE_TRUNC('WEEK', d)` while the spine side is retargeted to Sunday. Build the key with `week_trunc(source_col, week_start_of(inner_expr))`. |
| C2 | Critical | Alias-reuse CTE chain moves WHERE after the window and emits `SELECT *` with GROUP BY. | `from t where x > 1 select row_number() over (order by x) as rn, rn * 2 as d` (postgres) → rows `[(2,4),(3,6)]` vs correct `[(1,2),(2,4)]`; `from g where x > 1 group by a (sum(v) as s, s * 2 as d)` → binder error | `compiler/alias_reuse.py` `_generate_cte_chain_with_prefix` strips where/having off the base CTE. Keep WHERE and joins in the base; project group keys instead of `*`; HAVING stays on the base. |
| C3 | High | `spine by <categorical> (count(*))` is invalid SQL on every non-DuckDB dialect (docs "Status Dashboard"). | `from tickets spine by status (count(*) as ticket_count)` (postgres) → `COUNT(status)` aliased `status` makes alias_reuse build a chain with `SELECT * … GROUP BY` | `_rewire_to_spines` rewrites `COUNT(*)` to `COUNT(<key>)` whose name equals the projection alias. Count a qualified column or a presence marker. Ordering dependency spine→alias_reuse. |
| C4 | High | DuckDB list-comprehension regex corrupts SQL when the condition has parentheses. | `select [x * 2 for x in numbers if abs(x) > 1] as d` → `IF ABS(x] > 1)`; `[x for x in data.numbers]` is not matched and returns structs | `compiler/list_comprehension.py` `fix_duckdb_list_comprehensions` is a regex on generated text (called from `_apply_text_transforms`). Do it at the AST level. |
| C5 | High | GROUP BY alias that shadows a source column groups by the raw column. | `group by coalesce(region, 'unknown') as region (sum(amount) as s)` → `GROUP BY region` → `[('unknown',2),('unknown',3),('a',1)]` instead of `[('a',1),('unknown',5)]`; dialect-dependent (BigQuery resolves the alias) | `transpile.py` `_strip_group_by_aliases`. Emit the expression (or ordinal) when the alias collides with a referenced column. |
| C6 | High | `spine by … as alias` / `spine(...) as alias` loses the spine or emits broken SQL. | `group by spine(month(order_date)) as m (sum(amount))` → `SPINE(DATE_TRUNC(...)) AS m` survives into SQL; `spine by month(order_date) as m` → `GROUP BY DATE_TRUNC(...) AS m` | `_strip_group_by_aliases` runs before `_transform_spine`. Run it after, and unwrap `Alias` before building the key. |
| C7 | High | Date spines without WHERE bounds do no gap-filling on Snowflake/BigQuery/MySQL; BigQuery output is invalid. | `from orders spine by month(order_date) (sum(amount))` (snowflake) → `SELECT DISTINCT DATE_TRUNC('MONTH', order_date)` (no spine); bigquery swaps `DATE_TRUNC` args | `spine_helpers.py` `build_date_spine_from_data_sql` fallback builds dialect text by string. Build an AST with a `bounds` CTE per dialect, raise where no series generator exists. |
| C8 | High | Fanout pre-aggregation removes columns a later join's ON clause needs. | orders → order_items → products chain grouped by `products.name`: order_items is replaced by `(SELECT order_id, SUM(quantity) … GROUP BY order_id)` then `ON order_items.product_id = products.id` → binder error | `compiler/fanout.py` `_depends_on_many_side_shape` ignores other joins' ON clauses. Treat such references as "depends on raw rows". |
| C9 | Medium | Categorical spine with a NULL value counts 0 for the NULL group. | `spine by status (count(*) as n)` with statuses `('a', NULL, NULL)` → `[(None,0),('a',1)]` | `_rewire_to_spines` `COUNT(*)→COUNT(key)`; count a never-null marker from the source side. |
| C10 | Medium | Inline `SET` statements are ignored by the compile stage when no kwargs/schema are passed. | `SET include_transpilation_comments = false; … spine by month(d) …` still emits the spine comment; works once any kwarg is passed | `transpile.py` `asql_dialect = ASQL(**kwargs) if kwargs else "asql"`: the parser mutates a throwaway instance. Always instantiate. |
| C11 | Medium | A caller-supplied dialect instance is mutated (schema and `SET` leak across calls), contrary to the docstring. | `d = ASQL(); transpile("SET week_start = sunday; from users", read=d)` then a plain call on `d` emits Sunday weeks | `transpile.py` assigns `settings` on the passed object; build a fresh `ASQL(**{**read.settings, …})` per call. |
| C12 | Medium | Running/rolling windows inherit a query ORDER BY that names a projection alias → invalid SQL. | `from t select x, running_sum(x) as rs order by rs` → `SUM(x) OVER (ORDER BY rs …) AS rs` (binder error) | `_resolve_running_window_order` copies ORDER BY verbatim; resolve aliases to expressions first. |

Lesser compiler findings: `spine by year(d), month(d)` cross-joins two independent spines (16 rows instead of 8); `spine by hour(ts)` silently falls back to a DISTINCT spine; spine on a subquery FROM (or after fanout stage 2) silently degrades to plain GROUP BY; `except` with a joined table missing from the schema emits `users.* AS "*"` on Postgres (the same node bug fixed in `auto_qualify` in #4 still exists in `column_operators.py`); `except` + alias reuse duplicates columns; forward many-side join with no many-side aggregate collapses to `SELECT DISTINCT fk` and changes `COUNT(*)` while still warning about inflation; "fanout protection skipped" suppresses the inflation warning; GROUP BY aliases defeat stage-2 fanout protection; `alias_reuse._cte_counter` is process-global so CTE names differ between identical calls; `extract_date_bounds_from_where` mishandles strict `>` on DATE columns and is scope-blind to nested WHEREs; BigQuery gets `INTERVAL '7 days'` (invalid) in the main query but `INTERVAL '7' DAY` in the spine; `_transform_list_comprehension` is a no-op (the real work is the regex in C4).

**Ordering dependencies in `_apply_dialect_transforms`** (each one is a latent bug): `_strip_group_by_aliases` before spine (C6) and fanout; `_resolve_running_window_order` before alias_reuse (C12); fanout before spine (stage 2 makes FROM a subquery spine cannot read); spine before alias_reuse (C3); alias_reuse before column_operators (duplicated columns); `_apply_text_transforms` runs regexes over the final text, including user-written SQL.

## What the repo is missing (process)

- **Execution tests only run on DuckDB.** Every compiler finding above with a
  wrong result on Postgres/Snowflake/BigQuery was invisible to CI because
  those dialects are only parse-checked. A Postgres service container in CI
  (and a Snowflake/BigQuery smoke behind a secret) would have caught C2, C3,
  C7.
- **Docs examples are compiled but never executed.** The docs build proves
  they compile; several (P4, P5, P6, C3) produce SQL the engine rejects.
  Executing ` ```asql-play ` blocks against the playground's DuckDB schema in
  the test suite would catch this class.
- **No negative-parse tests.** P1 means any garbage after a clause is accepted.
  A test that every documented syntax parses *and* that known-bad inputs
  raise would hold the line.
- **Transform ordering is implicit.** `_apply_dialect_transforms` should
  state its order as data with the reason for each edge, and each transform
  should assert its preconditions (e.g. spine requires plain `Column` keys).
- **Settings isolation.** C10/C11: `transpile()` should never mutate a
  caller's dialect and should always run with an instance.
- **Repo hygiene**: no branch protection (documented in CONTRIBUTING.md, must
  be set by hand), no Dependabot/Renovate for the `uv.lock`/`npm` pins, no
  release tags (version 0.1.0 everywhere), `tests/e2e` (Playwright) not in CI,
  `vscode-extension/` untested, no coverage report.
